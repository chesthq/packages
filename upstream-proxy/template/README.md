# {{NAME}}

Templated upstream proxy generated by `@chest-gate/upstream-proxy`. Wraps an upstream API, holds the API key in this proxy's own environment, and forwards paid requests routed through chest gate.

> Best fit for APIs you own, run, or are explicitly licensed to redistribute. Many commercial APIs' terms of service restrict proxying access to your own end-users — check before wrapping someone else's endpoint.

```
agent ──▶ gate.chest.sh/g/<slug>/* ──▶ this proxy ──▶ {{TARGET_ORIGIN}}{{TARGET_PATH}}
                                            │
                                  injects {{HEADER_NAME}}
```

Chest gate, the agent, and any other party never see the upstream key.

## Setup

```bash
npm install
{{ENV_VAR_NAME}}=… npm run dev   # local smoke test
```

Hit `http://localhost:8787/__health` — should return `{"ok":true}`.

## Deploy to Vercel

1. **Bundle once.** `npm run bundle` produces `index.js` (self-contained).
2. **Push to a git repo**, then import into Vercel.
3. **Set the env var.**
   - Project Settings → Environment Variables
   - Name: `{{ENV_VAR_NAME}}`
   - Value: your upstream API key
4. **Deploy.** Vercel ships `index.js` as the function entry; `src/` is excluded via `.vercelignore` so Vercel's auto-detection can't shadow the bundle.

## Wire chest gate to it

```bash
chest deploy --upstream https://<your-vercel-url> --slug <your-slug> --price '$0.01'
```

## What this proxy enforces, per request

| Defense | What it does |
|---|---|
| Path allowlist | Rejects requests outside the configured path patterns. |
| Header strip | Drops the configured headers from the inbound request before forwarding (no smuggled creds from caller). |
| Auth inject | Adds exactly one upstream auth header, value sourced from `process.env.{{ENV_VAR_NAME}}`. |
| Egress allowlist | Only `{{TARGET_ORIGIN}}` is callable. SSRF-proof. |
| Response sanitisation | `set-cookie` and `www-authenticate` stripped from upstream responses. |

## Re-bundling

After editing `src/handler.ts`, run `npm run bundle` and commit the new `index.js`. Push deploys.

## Why isn't there a `build` script?

Naming the script `build` would make Vercel auto-run it during deploy. Combined with `.vercelignore` removing `src/`, that build step then fails with "Could not resolve `src/handler.ts`". The `bundle` name keeps Vercel out of it; the committed `index.js` is the deploy artifact.
